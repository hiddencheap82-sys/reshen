# نصب روی هاست cPanel

> برای کسی نوشته شده که SSH ندارد و فقط با File Manager و صفحات cPanel کار می‌کند.

---

## پیش‌نیازها

| مورد | حداقل | اگر نبود |
|---|---|---|
| PHP | ۸.۱ | cPanel → **Select PHP Version** |
| MySQL / MariaDB | ۵.۷ / ۱۰.۳ | تقریباً همه‌جا هست |
| `pdo_mysql`, `mbstring`, `json`, `curl`, `openssl` | ضروری | Select PHP Version → Extensions |
| `soap` | برای ملی‌پیامک | اگر نشد، کاوه‌نگار را ارائه‌دهندهٔ اصلی کنید |
| `mod_rewrite` | ضروری | روی cPanel همیشه هست |

نگران نباشید اگر مطمئن نیستید — **نصاب همه را بررسی می‌کند و می‌گوید چه چیزی کم است.**

---

## گام ۱ — آپلود

۱. در cPanel، **File Manager** را باز کنید.
۲. فایل `reshen.zip` را در `public_html` آپلود کنید.
۳. راست‌کلیک → **Extract**.

**کجا اکسترکت کنم؟**

| می‌خواهید آدرس چه باشد | کجا اکسترکت کنید |
|---|---|
| `example.com` | مستقیم در `public_html` |
| `example.com/reshen` | در `public_html/reshen` |
| `nobat.example.com` | در پوشهٔ همان زیردامنه |

هر سه حالت کار می‌کنند — لازم نیست document root را عوض کنید.

> **چرا؟** یک فایل `.htaccess` در ریشهٔ پروژه، درخواست‌ها را به پوشهٔ
> `public/` می‌فرستد و هم‌زمان پوشه‌های حساس را می‌بندد. پس «`/public`» در
> آدرس دیده نمی‌شود و کسی هم نمی‌تواند کد یا `.env` را دانلود کند.

---

## گام ۲ — ساخت دیتابیس

cPanel → **MySQL® Databases**:

۱. **Create New Database**: مثلاً `reshen` → ساخته می‌شود `myuser_reshen`
۲. **Add New User**: یک کاربر با رمز قوی
۳. **Add User To Database** → **ALL PRIVILEGES**

نام کامل دیتابیس و کاربر را یادداشت کنید — نصاب می‌خواهدشان.

---

## گام ۳ — اجرای نصاب

در مرورگر باز کنید:

```
https://example.com/install.php
```

سه گام دارد:

1. **بررسی محیط** — اگر چیزی کم باشد، دقیقاً می‌گوید چیست و چطور درستش کنید
2. **اتصال دیتابیس** — همان چیزی که در گام ۲ ساختید
3. **پایان** — جدول‌ها ساخته می‌شوند

نصاب در پایان `storage/installed.lock` را می‌سازد و **خودش را قفل می‌کند**.
برای امنیت بیشتر می‌توانید `public/install.php` را هم پاک کنید.

---

## گام ۴ — کرون (این را رد نکنید)

> **بدون کرون، هیچ پیامک یادآوری ارسال نمی‌شود** و صف زنده بی‌صدا می‌ماند —
> یعنی فیچر اصلی محصول کار نمی‌کند. علامتش این است که «همه‌چیز درست به نظر
> می‌رسد ولی پیامکی نمی‌آید» و هیچ خطایی هم جایی ثبت نمی‌شود.

توکن را بگیرید: وارد پنل شوید → **تنظیمات سالن** → بخش کرون.
(یا اگر SSH دارید: `php tools/cron.php --token`)

cPanel → **Cron Jobs** → Add New Cron Job:

| تنظیم | مقدار |
|---|---|
| Common Settings | Every 5 Minutes |
| Command | `curl -s "https://example.com/cron.php?token=TOKEN" >/dev/null 2>&1` |

اگر هاست شما دستور `php` را اجازه می‌دهد، این بهتر است (محدودیت زمان اجرا ندارد):

```
php /home/USER/public_html/tools/cron.php >/dev/null 2>&1
```

**بررسی:** ۱۰ دقیقه بعد، صفحهٔ `doctor.php` را باز کنید. ردیف «آخرین اجرای
کرون» باید زمانی نزدیک نشان بدهد.

---

## گام ۵ — پیامک

تا این لحظه `SMS_DRIVER=log` است، یعنی **هیچ پیامکی ارسال نمی‌شود** و کد ورود
فقط در `storage/logs/sms.log` نوشته می‌شود. برای سالن واقعی:

۱. از ملی‌پیامک یا کاوه‌نگار خط و اعتبار بگیرید
۲. **الگوی پیامک را ثبت کنید** — کد ورود روی خط خدماتی مشترک با متن آزاد
   ارسال **نمی‌شود**. تأیید الگو چند روز طول می‌کشد، پس همین امروز شروع کنید
۳. `.env` را از File Manager ویرایش کنید:

```ini
SMS_DRIVER=melipayamak
SMS_MELIPAYAMAK_USERNAME=...
SMS_MELIPAYAMAK_PASSWORD=...
SMS_MELIPAYAMAK_FROM=...
SMS_PATTERN_MELIPAYAMAK_OTP=12345      # شناسهٔ الگوی تأییدشده
```

کاوه‌نگار خودکار به‌عنوان پشتیبان استفاده می‌شود اگر تنظیم شده باشد.

---

## گام ۶ — اولین ورود

`https://example.com/` را باز کنید و شمارهٔ موبایلتان را بزنید.
**اولین کاربری که ثبت‌نام کند صاحب سالن می‌شود.**

اگر پیامک هنوز تنظیم نشده، کد ورود را از `storage/logs/sms.log` بردارید.

---

## عیب‌یابی

| نشانه | علت محتمل |
|---|---|
| صفحهٔ سفید | `APP_DEBUG=true` بگذارید تا خطا را ببینید — بعد حتماً برش گردانید |
| خطای ۵۰۰ روی همهٔ صفحات | `.htaccess` یا نسخهٔ PHP. `doctor.php` را باز کنید |
| صفحه بدون استایل | پوشهٔ `public/assets/` آپلود نشده |
| همهٔ لینک‌ها ۴۰۴ | `mod_rewrite` خاموش است یا `.htaccess` آپلود نشده (فایل مخفی است — در File Manager گزینهٔ Show Hidden Files را بزنید) |
| پیامک نمی‌رود | `doctor.php` → ردیف‌های `soap` و «آخرین اجرای کرون» |
| متن فارسی به‌هم‌ریخته | کدگذاری دیتابیس utf8mb4 نیست |

**قبل از هر تماس با پشتیبانی:** `doctor.php` را باز کنید و از صفحه عکس بگیرید.
تقریباً همیشه جواب همان‌جاست.

---

## به‌روزرسانی

۱. از `.env` و دیتابیس نسخهٔ پشتیبان بگیرید (cPanel → Backup)
۲. فایل‌های جدید را روی قبلی‌ها اکسترکت کنید — **`.env` و `storage/` را دست نزنید**
۳. `doctor.php` را باز کنید؛ اگر «مهاجرت‌های اجرانشده» داشت، `install.php`
   دیگر قفل است، پس مهاجرت را با حذف موقت `storage/installed.lock` و اجرای
   دوبارهٔ نصاب انجام دهید — یا با SSH: `php tools/migrate.php`

---

## چه چیزی نباید از وب قابل دسترس باشد

این‌ها را در مرورگر امتحان کنید؛ همه باید **403** یا **404** بدهند:

```
https://example.com/.env
https://example.com/app/Core/DB.php
https://example.com/config/database.php
https://example.com/storage/logs/sms.log
https://example.com/database/schema.sql
```

اگر هرکدام محتوا نشان داد، `.htaccess` ریشه آپلود نشده — فوراً درستش کنید.
