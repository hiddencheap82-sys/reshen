# ۰۶ — یکپارچه‌سازی‌های ایران

هر آنچه بیرون از کد ماست و بدون آن محصول در ایران کار نمی‌کند.

---

## ۱. پیامک — حیاتی‌ترین وابستگی

پیامک، تنها کانالی است که **تضمینی** به مشتری می‌رسد. اگر پیامک نرود، صف زنده بی‌صدا می‌شود و
کل ارزش محصول از بین می‌رود. پس **تک‌ارائه‌دهنده ممنوع**.

### معماری

```php
// app/Domain/Messaging/Contracts/SmsProvider.php
interface SmsProvider
{
    public function send(string $to, string $text): SmsResult;
    public function sendPattern(string $to, string $patternCode, array $vars): SmsResult;
    public function credit(): int;
    public function isHealthy(): bool;
}
```

پیاده‌سازی‌ها: `MelliPayamakProvider` (اصلی) · `KavenegarProvider` (پشتیبان) · `LogProvider` (توسعه)

`SmsManager` ارائه‌دهندهٔ اصلی را صدا می‌زند و در صورت خطا یا ناسالم بودن، **خودکار** به پشتیبان
سوئیچ می‌کند و هشدار می‌دهد.

### هشدار: ملی‌پیامک و `php-soap`

> از `tools/host-check.php` در همین ریپو: «پیامک ملی‌پیامک با SOAP کار می‌کند. بدون این، هیچ
> پیامکی نمی‌رود» — و این را «فقط وقتی می‌فهمید که اولین پیامک نرود.»

اقدام: بررسی `extension_loaded('soap')` در `php artisan reshen:doctor` و در راه‌اندازی اولیه،
نه موقع اولین ارسال.

### الگو (Pattern) — الزام قانونی

پیامک انبوه غیرتبلیغاتی در ایران باید با **الگوی از پیش تأییدشده** ارسال شود. پیامک آزاد روی خط
خدماتی رد می‌شود.

**پس:** همهٔ متن‌های ثابت باید از قبل به‌عنوان الگو ثبت و تأیید شوند. `sms_templates` کد الگوی
هر ارائه‌دهنده را نگه می‌دارد:

```php
'queue_nearly_up' => [
    'mellipayamak' => '12345',
    'kavenegar'    => 'reshen-nearly-up',
    'vars'         => ['customer', 'eta', 'salon', 'barber', 'token'],
],
```

> **این کار زمان‌بر است — تأیید الگو چند روز طول می‌کشد.** باید در هفتهٔ اول اسپرینت شروع شود،
> نه هفتهٔ آخر. در [برنامهٔ اسپرینت](../20-delivery/03-sprint-plan.md) به‌عنوان کار هفتهٔ ۱ آمده.

### شمارهٔ موبایل — نرمال‌سازی

ورودی‌های واقعی: `09121234567` · `9121234567` · `+989121234567` · `۰۹۱۲۱۲۳۴۵۶۷` (ارقام فارسی) ·
`0912-123-4567`

قاعده: همیشه به `989121234567` (فرمت E.164 بدون `+`) نرمال و ذخیره کن. نمایش به `0912 123 4567`.
یک `ValueObject` به نام `IranMobile` این را انجام می‌دهد و **هیچ‌جای دیگری** شماره دست‌کاری نمی‌شود.

### کنترل هزینه
سقف روزانه به ازای سالن · حذف پیامک تکراری در پنجرهٔ ۵ دقیقه‌ای · صف با اولویت (حیاتی > یادآور >
تبلیغاتی) · ثبت هزینهٔ هر پیامک در `sms_messages.cost`

## ۲. درگاه پرداخت

**زیبال** (اصلی) و **زرین‌پال** (پشتیبان). هر دو پرداخت‌یار دارای مجوز شاپرک و بانک مرکزی‌اند.

```php
interface PaymentGateway
{
    public function request(Money $amount, string $callbackUrl, array $meta): GatewayRedirect;
    public function verify(string $reference): GatewayVerification;
    public function refund(string $reference, Money $amount): RefundResult;
}
```

### کاربردها
| مورد | فاز |
|---|---|
| بیعانهٔ نوبت (C06) | ۲ |
| شارژ کیف پیامک (F07) | ۱ |
| اشتراک خود سالن نزد ما (G02) | ۲ |
| پرداخت کامل آنلاین خدمت | ۳ — اختیاری |

### قواعد
- مبلغ‌ها به **ریال** به درگاه می‌روند
- تأیید **همیشه** سمت سرور، هرگز بر اساس پارامترهای بازگشتی مرورگر
- وب‌هوک با امضای HMAC
- ایدمپوتنسی: `gateway_ref` یکتاست و پرداخت تکراری رد می‌شود
- عدم تطابق مبلغ ⇒ رد + هشدار به تیم

### واقعیتی که نباید فراموش شود
> **اکثر پول در آرایشگاه، نقدی و کارت‌به‌کارت است.** درگاه آنلاین در این صنف حاشیه است، نه مرکز.
> پس `payments.method` باید `cash` و `card_to_card` را به‌عنوان شهروند درجه‌یک داشته باشد و ثبتشان
> باید **سریع‌تر** از پرداخت آنلاین باشد. هر طراحی‌ای که آنلاین را مسیر اصلی فرض کند، در عمل
> استفاده نمی‌شود.

## ۳. تقویم شمسی — عمیق‌تر از نمایش

از کتابخانهٔ `morilog/jalali` یا معادلش استفاده می‌شود، ولی مسئله فقط تبدیل تاریخ نیست:

| موضوع | نکته |
|---|---|
| **آخر هفته** | پنجشنبه و جمعه، نه شنبه و یکشنبه. `weekday`: ۰=شنبه … ۶=جمعه |
| **شروع هفته** | شنبه. هر گزارش «هفتگی» باید شنبه شروع شود |
| **تعطیلات رسمی** | جدول `holidays`، به‌روزرسانی سالانه. سالن می‌تواند بازگشایی در تعطیل را دستی فعال کند |
| **نوروز** | اوج مطلق سال. ظرفیت باید از اسفند باز شود. سالن‌ها ساعت کاری ویژه دارند |
| **محرم و صفر** | افت شدید. ابزار تخفیف فصلی (E05) دقیقاً برای این است |
| **ماه رمضان** | جابه‌جایی ساعات کاری به عصر و شب |
| **سال کبیسه** | اسفند ۳۰ روزه. کتابخانه باید درست حسابش کند — تست داشته باشد |
| **ذخیره‌سازی** | دیتابیس میلادی و UTC. تبدیل فقط در نمایش. ([۰۳ §۹](03-data-model.md)) |

**ارقام:** ورودی هم فارسی هم لاتین پذیرفته شود (کاربر با کیبورد فارسی تایپ می‌کند)، خروجی همیشه
فارسی. یک `Helper` سراسری، نه `str_replace` پراکنده در کد.

## ۴. نقشه

**نیازمندی فاز ۴** (جستجوی «نزدیک من»). Google Maps در دسترس نیست.

| گزینه | |
|---|---|
| **نشان (Neshan)** | نقشهٔ ایرانی، API مناسب، آدرس‌های فارسی دقیق — **انتخاب پیشنهادی** |
| OpenStreetMap + Leaflet | رایگان، ولی پوشش آدرس ایران ضعیف‌تر |
| بلد (Balad) | جایگزین |

در فاز ۱ فقط `lat`/`lng` ذخیره می‌شود و لینک به نقشه داده می‌شود؛ نقشهٔ تعاملی لازم نیست.

## ۵. پوش نوتیفیکیشن

**Firebase در دسترس نیست و نباید به آن وابسته شد.**

راه‌حل: **Web Push استاندارد با VAPID**، خودمیزبان. روی کروم اندروید کار می‌کند (اکثریت مطلق
بازار ایران). روی iOS فقط اگر PWA به صفحهٔ اصلی اضافه شده باشد.

**پس پیامک، کانال اصلی می‌ماند و پوش فقط مکمل است** — ولی مکملی که هزینهٔ پیامک را پایین می‌آورد.
هر کاربری که پوش را فعال کند، ماهی چند هزار تومان صرفه‌جویی است.

## ۶. انتشار در فروشگاه‌های ایرانی (فاز ۳)

گوگل‌پلی در دسترس نیست. **کافه‌بازار** و **مایکت**.

روش: **TWA** (Trusted Web Activity) — همان PWA در یک پوستهٔ اندرویدی. یک کدبیس، دو خروجی.

| نکته | |
|---|---|
| بازار بازبینی انسانی دارد؛ چند روز طول می‌کشد | |
| نیازمند نماد اعتماد الکترونیکی (اینماد) برای اپ‌های دارای پرداخت | **این را زود شروع کن، وقت‌گیر است** |
| دو اپ جدا (مشتری / آرایشگر) مثل موکات؟ ← [تصمیم باز ت۴](../00-product/05-prd.md#۸-تصمیمهای-باز) | |

## ۷. سامانهٔ مؤدیان

**وضعیت فعلی:** طبق مادهٔ ۱۴ مکرر، اشخاص حقیقی با فروش سالانهٔ کمتر از حد نصاب (**۱۲ میلیارد
تومان در ۱۴۰۵**) می‌توانند از صدور صورتحساب الکترونیکی معاف شوند. **تقریباً همهٔ آرایشگاه‌های
هدف ما زیر این سقف‌اند.**

**پس:** فاز ۳، و فقط اگر مشتری واقعی درخواست کرد. ولی **معماری باید آماده باشد**:
- `payments` و `product_sales` همهٔ فیلدهای لازم صورتحساب را دارند
- شناسهٔ یکتای مالیاتی و شمارهٔ اقتصادی در `salons.settings` جا دارد
- اتصال از طریق یکی از شرکت‌های معتمد ارائه‌کنندهٔ خدمات مالیاتی (حدود ۲۰ شرکت مجاز)

> **این را زودتر نساز.** هزینه‌اش بالا و ارزشش برای بازار هدف ما تقریباً صفر است.

## ۸. زیرساخت

| مورد | تصمیم |
|---|---|
| هاست | VPS ایرانی. **هیچ سرویس زمان‌اجرا بیرون از ایران** |

| وابستگی‌ها | Composer و npm در CI **کش** شوند — دسترسی به مخازن خارجی ناپایدار است و یک روز بیلد را می‌خواباند |

## ۹. چک‌لیست نصب روی هاست مشتری

`tools/host-check.php` موجود در ریپو همین حالا این‌ها را می‌سنجد و باید برای رشن به‌روز شود:

- [ ] PHP ≥ ۸٫۲
- [ ] `soap` ← **بدون این هیچ پیامکی نمی‌رود**
- [ ] `curl`, `openssl`, `mbstring`, `json`, `zip`, `intl`
- [ ] `memory_limit` ≥ ۲۵۶M
- [ ] خروجی HTTPS باز (زیبال، ملی‌پیامک)
- [ ] توابع `fsockopen`, `proc_open` غیرفعال نشده باشند
- [x] ~~cron در دسترس~~ — دیگر لازم نیست؛ کارهای دوره‌ای با بازدید وب اجرا می‌شوند

> یادآوری از همان فایل: **بعد از خواندن نتیجه، فایل را از سرور پاک کنید.**
