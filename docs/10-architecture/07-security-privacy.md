# ۰۷ — امنیت و حریم خصوصی

دارایی‌ای که محافظت می‌کنیم: **شمارهٔ موبایل، عکس و عادت‌های صدها هزار نفر.** نشت این داده،
پایان پروژه است — نه یک حادثه.

---

## ۱. مدل تهدید

| تهدید | اثر | دفاع |
|---|---|---|
| **نشت داده بین سالن‌ها** | فاجعه‌بار — کل بازار یک شهر | اسکوپ سراسری + آزمون معماری + کلید خارجی مرکب ([۰۲](02-multitenancy.md)) |
| **حدس زدن `public_token`** | دیدن نوبت دیگران | ۱۲ کاراکتر تصادفی امن (۷۱ بیت آنتروپی) + محدودسازی نرخ |
| **سوءاستفاده از OTP** | تصاحب حساب | ۵ تلاش، قفل ۱۵ دقیقه، کد هش‌شده، بدون لاگ |
| **رزرو انبوه خودکار** | خرابکاری رقیب | تأیید شماره پیش از رزرو + سقف ۵ رزرو در ساعت |
| **بمباران پیامکی (تخلیهٔ کیف)** | ضرر مالی سالن | سقف ۳ درخواست کد در ساعت به ازای شماره + سقف روزانهٔ سالن |
| **آرایشگرِ اخراج‌شده** | خروج دادهٔ مشتریان | لغو فوری نشست‌ها + ثبت لاگ خروجی‌ها |
| **سوءاستفادهٔ کارمند ما** | نشت | ورود پشتیبانی همیشه ثبت می‌شود + اطلاع به سالن |
| **عکس مشتری** | آبرو | رضایت صریح + مسیر غیرقابل‌حدس + بدون دسترسی مستقیم |
| **دستکاری مبلغ پرداخت** | ضرر | تأیید سمت سرور + تطبیق مبلغ |

## ۲. کمینه‌سازی داده

چیزهایی که **جمع نمی‌کنیم**:

| | چرا |
|---|---|
| کد ملی | لازم نیست و مسئولیت حقوقی می‌آورد |
| آدرس منزل مشتری | ما سرویس در محل نیستیم |
| اطلاعات کارت بانکی | همیشه در درگاه می‌ماند، هرگز پیش ما |
| موقعیت مکانی لحظه‌ای مشتری | وسوسه‌انگیز است («نزدیک سالنی؟») ولی ارزشش را ندارد |
| مخاطبین گوشی | |

**نگهداشت:**
| داده | مدت |
|---|---|
| نوبت‌ها | ۳ سال، سپس آرشیو بی‌نام |
| عکس مشتری | تا زمان درخواست حذف — یا خودکار پس از ۲ سال بی‌مراجعگی |
| لاگ پیامک | ۱ سال |
| لاگ ممیزی | ۲ سال |
| `public_token` | ۷ روز پس از پایان نوبت |

## ۳. اجرای فنی «قرارداد عدم‌واسطه‌گری»

قول [۰۶ §۹](../00-product/06-pricing-business-model.md) به سالن‌ها **باید کد باشد**، چون یک بار
نقضش کل بازار را می‌برد ([R4](../00-product/09-risks.md)):

| قاعده | اجرا |
|---|---|
| سالن A هرگز پروندهٔ مشتری در سالن B را نمی‌بیند | `customers` با `salon_id` اسکوپ می‌شود؛ هیچ API‌ای دسترسی بین‌سالنی ندارد |
| مشتری سالن A در نتایج تبلیغاتی سالن B ظاهر نمی‌شود | `NonSolicitation::mayTarget()` پیش از هر کمپین |
| ما شمارهٔ مشتریان یک سالن را به سالن دیگر نمی‌دهیم | هیچ اندپوینت خروجی سراسری وجود ندارد |
| سالن می‌تواند دادهٔ مشتریانش را ببرد | خروجی اکسل — دادهٔ او مال اوست |

و یک آزمون که هرگز حذف نمی‌شود:
```php
test('کمپین سالن نمی‌تواند مشتری ثبت‌شدهٔ سالن دیگر را هدف بگیرد');
test('API پنل هرگز مشتری سالن دیگر را برنمی‌گرداند');
```

## ۴. احراز هویت و دسترسی

| | |
|---|---|
| ورود | فقط موبایل + کد یک‌بارمصرف |
| کد | هش‌شده در دیتابیس، هرگز در لاگ |
| نشست پنل | ۳۰ روز، قابل لغو |
| نشست پلتفرم‌ادمین | **۸ ساعت** |
| ورود پشتیبانی به سالن | **۳۰ دقیقه**، فقط خواندنی مگر با تأیید صریح، همیشه در لاگ |

**نقش‌ها:**

| نقش | صف | مشتریان | خدمات و قیمت | گزارش مالی | تسویه | تنظیمات |
|---|---|---|---|---|---|---|
| صاحب | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| مدیر | ✓ | ✓ | ✓ | ✓ | — | جزئی |
| آرایشگر | فقط خودش | فقط مشتریان خودش | — | **فقط درآمد خودش** | فقط فیش خودش | — |
| پذیرش | ✓ | ✓ | — | — | — | — |

> **آرایشگر درآمد بقیه را نمی‌بیند.** این فقط یک قاعدهٔ امنیتی نیست — اگر رضا ببیند حسن بیشتر
> درآورده، در سالن دعوا می‌شود و صاحب سالن نرم‌افزار را کنار می‌گذارد.

## ۵. عکس مشتری

حساس‌ترین دادهٔ ماست.

- **بدون `consent_at` ثبت نمی‌شود** — نه چک‌باکس پیش‌فرض‌تیک‌خورده
- مسیر فایل تصادفی و غیرقابل‌حدس، **بیرون از `public/`**
- سرو از طریق کنترلر با بررسی مجوز، نه لینک مستقیم وب‌سرور
- فقط صاحب سالن و آرایشگرِ همان مشتری می‌بینند
- حذف به درخواست مشتری، بی‌قید و شرط، ظرف ۴۸ ساعت
- در خروجی اکسل، عکس نیست

---

## ۶. پایه‌های امنیت اپلیکیشن

- Laravel: CSRF، هش Bcrypt/Argon2، ORM در برابر تزریق SQL
- هیچ `DB::raw` با ورودی کاربر
- خروجی Blade همیشه اسکیپ‌شده؛ `{!! !!}` نیازمند بازبینی
- هدرها: `Content-Security-Policy`، `X-Frame-Options: DENY`، `Referrer-Policy: same-origin`
- HTTPS اجباری، HSTS
- آپلود: بررسی نوع MIME واقعی، تغییر نام، حذف EXIF (موقعیت مکانی!)، سقف ۴ مگابایت
- `.env` هرگز در گیت
- وابستگی‌ها: `composer audit` و `npm audit` در CI

---

## ۷. ثبت ممیزی

هر یک از این‌ها در `audit_logs` می‌رود (چه کسی، چه چیزی، کِی، از کجا):

- ورود پشتیبانی ما به حساب سالن ✱
- تغییر نقش کاربر
- حذف یا خروجی گرفتن از مشتریان
- نهایی کردن تسویه
- تغییر قیمت خدمت
- حذف نوبت
- ورود ناموفق مکرر

✱ به سالن هم اطلاع داده می‌شود.

**لاگ‌ها هرگز نباید داشته باشند:** کد OTP · توکن نشست · `public_token` · شمارهٔ کامل (چهار رقم آخر کافی است)

## ۹. آنچه به سالن می‌گوییم

متن ساده‌ای که در قرارداد و در پنل می‌آید:

> - مشتریان شما مال شماست. هر وقت خواستید، فهرستشان را خروجی بگیرید.
> - ما شمارهٔ مشتریان شما را به هیچ آرایشگاه دیگری نمی‌دهیم و نمی‌فروشیم.
> - وقتی رشن به سامانهٔ سراسری تبدیل شود، مشتریان ثبت‌شدهٔ شما هرگز به آرایشگاه دیگری
>   پیشنهاد نمی‌شوند.
> - اگر کسی از تیم ما برای پشتیبانی وارد حساب شما شود، خودتان مطلع می‌شوید.
> - عکس مشتری فقط با اجازهٔ خودش ذخیره می‌شود.

این متن، هم اخلاق است هم بازاریابی. رقبا چنین چیزی ندارند.
